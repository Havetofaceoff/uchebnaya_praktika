# Проектирование базы данных в 3NF

Назначение

База данных предназначена для хранения информации о партнерах, товарах и истории отгрузок.

Схема позволяет:

- просматривать данные партнеров;
- редактировать данные партнеров;
- хранить информацию о товарах;
- просматривать историю отгрузок;
- получать объем продаж каждого партнера.

Сущности

1. partners

Хранит информацию о партнерах.

Основные поля:

- id — первичный ключ (PK);
- name — название партнера;
- inn — ИНН, уникальное значение;
- email — электронная почта, уникальное значение;
- phone — номер телефона;
- rating — рейтинг партнера.

2. products

Хранит информацию о товарах.

Основные поля:

- id — первичный ключ (PK);
- name — название товара;
- article — уникальный артикул;
- price — цена товара.

3. sales_history

Хранит историю отгрузок товаров партнерам.

Основные поля:

- id — первичный ключ (PK);
- partner_id — внешний ключ (FK) на partners;
- product_id — внешний ключ (FK) на products;
- quantity — количество товара;
- delivery_date — дата отгрузки.

Связи

Один партнер может иметь много записей в истории отгрузок:

partners 1:N sales_history

Один товар может присутствовать во многих отгрузках:

products 1:N sales_history

Нормализация

Схема приведена к третьей нормальной форме (3NF).

Данные о партнерах хранятся только в таблице partners, данные о товарах — только в products, а sales_history содержит данные конкретной отгрузки и внешние ключи на партнера и товар.

Это позволяет избежать дублирования данных и обеспечивает целостность базы данных.
